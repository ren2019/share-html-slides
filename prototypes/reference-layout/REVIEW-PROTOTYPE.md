# 审阅 UI 临时原型

问题：在现有材料阅读页，哪种结构最适合低摩擦手机评论？

- A：底部轻入口，按需展开底部评论面板。
- B：顶部审阅工具与边缘选段按钮，主动选段时正文显示逐段提示。
- C：桌面正文与评论双栏，手机按需打开评论面板。

启动：本目录先安装依赖，然后 `npm run review-prototype`。
阅读地址：`http://localhost:8878/read/2?variant=A`（长网页）与 `/read/3?variant=A`（幻灯片）。
底部箭头及非输入状态的左右键循环 A/B/C；参数可复制，刷新会重置内存状态。

展开顶部「审阅原型」可以切换访客 A、访客 B、发布者，模拟关闭评论、更新版本、满额，并查看全部演示状态。该控制区不是产品权限机制。

## 范围与当前结论

- 可体验选字动作入口、选段、整份评论、发送、回复、解决／重新打开、按身份过滤及限制状态。
- 三个方案供比较，尚无用户选定方案；不得将任何一个称为已批准设计或合并到正式代码。
- 保留现有合成阅读内容、品牌与阅读路由。当前基于已提交的原型快照，不含其他任务正在修改的首页或阅读界面。
- 内存数据、模拟身份；没有数据库、真实鉴权、防滥用或 CLI。关联 iframe 内的选择不覆盖；真实隔离上传 HTML 的桥接尚未验证。
- 更新按钮只模拟版本元数据，不修改正文。顶部调试区可看到全部合成评论，不代表真实产品的可见性。
- 390px 浏览器视口检查仅验证响应式布局，不证明 iOS／Android 微信原生长按或软键盘行为。

## 本轮手动检查

浏览器走通选段、输入、发送；模拟发布者看到全部评论并解决，显示重新打开；URL 切换 A/B 保留内存评论。类型检查通过。React Doctor 提示的复杂度等原型／既有问题未做产品化重构；路由已加 Suspense。
