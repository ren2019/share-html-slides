# 上传装订 UI 原型

Throwaway prototype，不是生产代码，无真实上传或持久化。

问题：面对独立发布的关联 HTML，材料库侧面板、三步向导、文件关系工作台，哪种结构最容易理解？

运行：在项目根目录执行 `python3 -m http.server 8876 --bind 127.0.0.1 --directory prototypes/upload-flow`，打开 http://localhost:8876/?variant=A 。B、C 用相同 query 切换，也可使用底部箭头或键盘左右键；输入和弹窗内不拦截。

可演示：选择合成 HTML、发现缺失、补齐、预览、仍然发布、独立材料分享、主题切换和重置。状态仅在内存，URL 只记布局；下方状态面板和 console 输出相关状态。示例链接使用 .example，不是真实分享。

当前 verdict：待用户比较选择，未验证任何布局为胜出方案。主题和品牌来自已定稿要求，几何图标为原型近似，非最终标志母版。

无现有应用页面与路由，采用独立 prototype 文件。原型仅保存在 prototype/upload-flow 分支，不合入 main，不进入生产构建；没有建立生产构建入口。

浏览器检查：已实际点击完整补齐→预览→发布三份→分享弹窗，以及缺失→确认仍然发布一份；已检查 A/B/C 切换和主题切换。这些仅验证原型交互可运行，不代表真实上传或微信验收。
