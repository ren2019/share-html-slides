## Standards

独立规范审查发现 1 项明确问题、2 项判断性建议：

1. `config.ts` 在短信 URL 存在但 token 缺失时，仍校验短信 HTTPS；生产中残留 HTTP URL 使所有身份入口失败，违反渠道相互独立要求。修复只在短信配置完整时校验网关；保留已启用短信必须 HTTPS 的限制。
2. 本人材料查询在 API 和页面重复，可在后续材料行为实现时共用；这是维护性建议，不构成当前权限缺陷。
3. 短信发送与认证配置同文件可进一步拆分；已有逻辑接缝，不能仅凭文件位置认定违反隔离要求。

问题 1 已在原始生产镜像复现：SMTP 配置完整、短信只有 HTTP URL，访问 `/login` 返回 500。新增配置边界回归覆盖缺失 token 下的 HTTP/无效 URL、关闭所有发送渠道后的可解析配置，以及完整配置仍拒绝非 HTTPS 网关。该回归加入 `pnpm test`；真实发码验收仍独立保留。
